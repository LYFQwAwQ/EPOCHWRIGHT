## 文档用途

EPOCHWRIGHT 是一个计划融合城市建造、养成、自动战斗和跨时代演进的网页策略游戏。这组文档当前重点定义俯视角、网格化的自动沙盘战斗系统。战斗由 AI 完成，玩家只负责观察和暂停；部队、出生区域、外交关系及战斗目标最终由城市、养成和世界系统传入。

文档同时描述完整目标架构和分阶段实现范围。完整设计用于保证扩展方向一致，实施路线用于避免把全部目标一次性塞入首个版本。

## 已确认的核心决策

| 主题 | 决策 |
| --- | --- |
| 战斗形式 | 即时自动演算，可暂停，不允许玩家下达战术命令 |
| 地图 | 正方形网格，默认每格 `4m x 4m`，支持量化高度和平滑 3D 表现 |
| 单位粒度 | 编组负责 AI；成员和载具独立记录伤亡或损坏 |
| 兵种 | 步兵、轮式、履带式、炮兵、旋翼/悬停空军；固定翼接口预留 |
| 伤亡 | 健康状态与在场状态分轴记录；不设置投降 |
| 战斗节奏 | 偏游戏化，依靠掩体、命中率、压制和机动延长交火，不使用超长生命条 |
| 情报 | 有限情报、发现进度、最后已知位置、势力与同盟通信延迟 |
| 外交 | 支持敌对、中立和同盟；同盟可共享有延迟的情报 |
| 模式 | 冲突模式与限时区域占领式防守模式 |
| 出生 | 开局部署，无复活；地图边缘可配置增援入口与撤离出口 |
| 弹药 | 首版无限备用弹药，但保留弹匣、射击节奏和换弹 |
| 友军伤害 | 关闭；非敌对单位仍阻挡空间和射线 |
| 地图来源 | 当前只使用参数化随机地图；生成器与战斗模块分离 |
| 表现 | 轻量 3D、基础几何体、实例化渲染、倾斜正交俯视镜头 |
| 平台 | 首版优先支持桌面浏览器，不承诺移动端体验 |
| 回放 | 首版不做回放 UI，但核心保持固定步长和确定性随机 |

## 术语

- **势力（Faction）**：拥有部队、情报和外交关系的独立参与方。
- **关系（Relation）**：两个势力间的敌对、中立或同盟状态。
- **战术编组（Tactical Group）**：最小完整 AI 单位，例如步兵小队、坦克排或炮组。
- **成员（Member）**：编组内的具体人员，可受伤、失能或死亡。
- **平台（Platform）**：坦克、车辆、火炮或飞行器等装备实体，可包含乘员岗位与部件。
- **有效战力（Combat Effective）**：仍能执行当前模式核心任务的编组或成员。
- **接触信息（Contact）**：某势力对敌方单位的非实时认知，而不是敌方真实状态。
- **防守点（Defense Objective）**：由一个或多个网格组成、可被争夺和占领的目标区域。

## 文档约束

- 所有具体数值均应配置化；文档中的数值是默认值或性能预算，不是不可修改的规则。
- 战斗核心不得依赖 React、Three.js、DOM 或浏览器计时器。
- 表现层不能成为战斗真相来源。是否可见、是否命中以及是否占领均由模拟核心决定。
- 随机地图、战斗模拟和观察客户端是三个独立模块，通过标准数据接口连接。
- 新时代、新兵种和英雄应通过数据与已注册能力扩展，不通过散落的兵种名称判断实现。
