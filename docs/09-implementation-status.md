## 已完成：阶段 0、阶段 1、阶段 2、阶段 3 车辆闭环与炮兵直接火力

### 模拟核心

- 纯 TypeScript、固定 `20Hz`、显式 `step()`。
- 相同规则、种子和输入产生相同状态哈希与结果。
- `map-2` 标准地图 schema，使用 TypedArray 分层保存高度、地表类型、水深、地面阻挡标志和静态对象占用。
- 地图生成输入支持到 `512 x 512`，并在分配 TypedArray 前限制总格数与长宽比。
- 地表层可表达草地、沙地、泥地、岩石和铺装；水深层可表达无水、浅水和深水，沼泽由泥地与浅水组合表达。
- 参数化随机高度，以及按全图格数兑现的山地、开阔水体和湿地占比；开阔水体包含深浅分层，湿地由泥地与浅水组合生成，不可满足的配额会明确拒绝。
- 按全图格数确定性生成树木、岩石和墙段；对象具有全局稳定 ID、单格锚点和 8 向朝向，对象列表与稠密占用投影会逐格交叉验证。
- 三类静态对象均阻挡步行并以类型高度参与视线；两侧出生部署带和跨图主进攻通道不会被山地、水体或静态对象切断，完整 setup 使用 A* 验证撤离与攻防任务路线。
- 从静态对象稳定字段确定性派生相邻可站立掩体槽位；树木、岩石和墙体容量分别为 2、4、6 名有效成员，冲突槽位按稳定对象 ID 选择。
- 掩体占用在出生与到达时声明，在完成离开、撤离或失去全部有效成员时释放；占用进入状态哈希并通过编组 inspection 投影。
- 命中与发现读取同一方向性掩体效果；正面完整、侧面减半、侧后方和后方无效，容量不足按实际覆盖成员比例缩放。
- 防守方在无敌情时只按公开目标和静态地图优先分配掩体阵位；高压制编组按直接、本地最后已知或共享接触快照评估 6 格内方向性掩体。
- 掩体评分综合防护、隐蔽、覆盖人数和路径成本，并为当前/已选槽位提供迟滞；未知敌军真实占用不会改变候选，实际移动仍遵守权威碰撞。
- 掩体选择原因、主要整数评分、评估 tick 和可选威胁快照进入状态哈希，并通过编组 inspection 投影。
- 静态地图连通分量在模拟初始化时派生，AI 目标落点只会选择编组当前可达的地形分量。
- 最后已知接触若落在弃置或摧毁平台的静态占用格，AI 会按距离、路径成本和稳定格索引选择最近可达落点，不会以空路径停在残骸目标上；其他无路目标和拥堵退避语义保持不变。
- 直接接触目标会先按己方当前可用武器效果检查适配性；攻击有人平台至少需要 `platform-damage`，只有人员伤害或压制效果的步枪编组不会进入对完整车辆无效的 `engaging` 空转状态，且仍可选择可伤害的溃散步兵。
- 直接与最后已知目标使用同一数据驱动整数效用：武器效果、情报置信度/新鲜度、距离、公开任务相关性、当前目标迟滞和直接接触奖励分项进入哈希与 inspection；同分按观察 tick 和稳定目标 ID 决定。
- 已知接触保存观察时的目标势力与 `personnel|platform` 快照；目标排序、运输威胁和共享情报不会读取未观察到的敌军当前位置、平台状态或脆弱性。
- 数据表驱动的步行成本矩阵；浅水和沙地减速、泥地浅水组合成本更高、深水不可通行。
- 地图、寻路与编组运行时已支持 `foot/wheeled/tracked` 三种移动类型；轮式偏好铺装并不能通过湿地，履带以较低粗糙地表代价通过湿地，两类车辆均拒绝深水和超过各自相邻高差阈值的步骤。
- EasyStar 封装的八方向 A*、统一地形成本和禁止切角。
- `BattleSetup` schema 为 `stage-3.1`、rules 为 `stage-3.7`、内容为 `content-3`；地图使用独立 `map-2` 版本。旧 `stage-2`/`stage-2.1`/`stage-2.2` 输入会补入等价默认内容、模板 ID、空平台和空运输关系；`stage-3` 的 `stage-3.0` 至 `stage-3.6` 规则输入会显式迁移，`content-2` 武器的顶层射程、瞄准和弹道字段会转换为行为等价的单一 `direct` fire mode。
- 数据驱动的时代、编组、成员、平台、部件、岗位、传感器和武器模板；当前输入必须显式携带内容包、模板引用、每组平台数组和顶层运输关系数组，时代白名单、引用、编制槽位、数值范围与当前支持能力在初始化时验证。
- 默认内容用 `infantry-rifle-squad-v1`、`infantry-rifleman-v1`、`infantry-eyesight-v1` 和 `rifle-standard-v1` 完整表达现有八人步枪小队，不按兵种或时代名称分支。
- 默认内容另提供各一组轮式和履带平台，编制包含驾驶员、炮手和替补乘员，传感器与平台武器通过部件所需岗位声明能力，并具有 8 单位运输容量与模板化上下车时间；首个运行时限制为每组最多一个平台，验证初始岗位资格、全局稳定 ID、八向朝向及平台移动类型的出生/撤离/任务路线。
- 默认内容提供一组自行火炮编组、履带炮兵平台和榴弹炮模板；展开规则显式引用炮手岗位与主武器部件，当前榴弹炮使用一个已实现的 `direct/logical-projectile` mode，间射 mode 仍会在初始化时拒绝。
- 炮兵平台以 `packed/deploying/deployed/packing` 四态推进固定展开/收炮 tick。未收炮不能转向或移动，要求展开的武器未完成展开不能开火；移动请求会先收炮，动作中失去必要岗位/部件或平台失效会稳定取消并回到前一稳定态。
- 直接逻辑弹丸只在当前直接接触、射程、视线和动态阻挡都合法时发射；发射立即消耗弹匣并进入冷却，新弹丸最早下一 tick 命中，发射方随后失效、撤离或被摧毁不会删除在途事实。
- 逻辑弹丸按整数距离计算至少 1 tick 的飞行时间，使用固定整数抛物线和稳定 supercover 顺序检测地形/静态对象碰撞；初始化限制最大飞行 tick、轨迹中间乘积和地图尺度，保证结算有界且不溢出安全整数。
- 弹着按格、平台和成员稳定枚举爆区，使用整数距离衰减；人员伤情与平台穿透使用互不串扰的 `blast-member-effect`/`blast-platform-effect` 随机键，只影响弹着时仍合法的敌对实体，不造成友军或非敌对伤害。
- 已有弹丸先推进，再与本 tick 合法直接射击共同收集和结算；事件稳定输出带 mode/弹丸 ID 的 `weapon-fired`、`projectile-impacted`，随后才输出伤情或部件事实。
- 普通消灭/溃散终止候选等待在途弹丸后重新判定；目标完成、时限、最大时长和僵局会冻结胜负/目标快照并进入只推进既有弹丸的 `settling`。结果记录 trigger/completed tick 和触发时弹丸数，完成时无残留弹丸，终止后继续冻结。
- 展开状态、剩余 tick、返回态、直射/间射/任务计数、完整弹丸效果快照与终止结算阶段进入状态哈希；本方 inspection、事实事件和平台结果投影保持同一事实。
- 平台使用单格锚点与编组占用，移动前按最短八向角差等待模板化转向 tick；移动、观察和平台武器分别由可用部件与有效岗位共同派生，失能、死亡、撤离或正在换岗的成员不提供岗位能力。
- 同车合格或允许替代的成员会按资格效率和稳定成员 ID 确定性换岗，且不会通过腾空另一个有效必需岗位造成循环换岗；来源与目标岗位在固定换岗 tick 内同时停用，替补受伤会取消并重新选择。换岗完成时与失能岗位成员交换岗位，保持成员健康、在场和车内位置守恒；替代效率会按基点降低移动推进、观察距离和平台武器命中。
- 平台武器具有独立弹匣、换弹和射击冷却；武器只有显式携带 `platform-damage` 效果时才能伤害平台，默认自动炮同时具有人员与反载具效果，步枪不会按目标名称临时获得穿甲能力。
- 地面直射按攻击方向与八向车体朝向确定正面、侧面或后方，只有显式 `top-attack` 效果使用顶部；装甲/穿透整数通过固定基点曲线结算，未穿透时只会按效果损伤加权选择的外露部件，穿透后独立选择部件和至多一名有效乘员。
- 结构、动力、行走、武器和传感部件使用独立完整度及 `operational/damaged/disabled/destroyed` 状态；同 tick 平台伤害先完整收集再按稳定 ID 结算，部件选择、乘员选择、穿透和伤情使用互不串扰的稳定随机键。
- 失去机动但仍有武器的平台保留固定火力；失去作战能力但可移动的平台撤离，机动与作战能力都丧失时乘员弃车。平台摧毁只由结构部件决定，不默认杀死乘员；弃车后平台保留独立权威格与静态占用，乘员转为徒步并只自卫、集结和撤离。
- 有效车辆在直接接触下先保持合法当前射击位并按最短八向角差把正面装甲朝向目标；当前位无效时按射程、路线成本、到达朝向和稳定迟滞评分候选，只对廉价评分前 12 名寻路。已经开始的单格转向或移动会保留到完成，之后才按最新目标重规划，且从当前锚格开始。选位原因、分项与目标进入哈希和 inspection。
- 顶层 `transportAssignments` 显式授权同势力平台与无平台乘客编组配对；验证器检查稳定关系 ID、唯一乘客关系、容量、初始同锚点和同部署批次，跨波次非初始配对会等双方实际部署后再启用。
- 初始搭载和同波次增援搭载原子建立成员 `passenger` 位置；车内编组锚点随平台移动，但不声明地面占用、掩体、感知、射击或目标占领力，也不会作为独立敌方接触。
- AI 只依据新鲜本地接触快照、公开目标距离、乘客士气和平台状态启动整组上下车；平台受损、失去机动或失去作战能力时优先卸载。配对双方在模板化持续时间内停驻，平台移动、失能或目标格被占会取消动作，完成时一次性转换全部已部署成员。
- 战术下车在全部合法相邻格中按已知威胁距离、平台遮蔽和目标距离稳定评分；未知敌军真值不影响选择。触发原因、选择格、分项和威胁快照进入运输状态哈希与 inspection。
- 已下车编组在无新鲜威胁且离任务区足够远时会与配对平台会合并重新搭载；未配对编组永远不进入候选。
- 平台失效会强制乘客下车，结构摧毁先按稳定成员 ID 结算一次乘客伤情；没有相邻合法容量时保持 `trapped` 并逐 tick 按稳定格序重试，最终成员位置与平台乘客列表进入 inspection、事件、结果和状态哈希。
- 平台格、朝向、部件、岗位、武器状态与派生三轴进入哈希、己方 inspection、事实事件和结果；终止后保持冻结。
- 模拟从模板读取感知/武器射程、弹匣、换弹、射击间隔、伤害、压制、暴露、防护、抗压制和占领力；内容规范哈希、模板引用和运行时武器身份进入确定性哈希。
- 随机演示生成器位于独立 `src/demo` 模块，只产出经过标准验证的完整 `BattleSetup`；模拟公共 API 不再暴露演示选项或生成器。
- Worker 初始化与客户端 `start()` 只接收完整 `BattleSetup`，演示和未来城市/养成系统可通过同一稳定入口接入；模拟在创建运行时状态前再次验证输入。
- 演示生成器默认输入仍是两势力、每组固定 8 人的步枪编组；网页演示启动配置使用三方（赤焰/苍蓝/橄榄），其中苍蓝与橄榄同盟、共同对抗赤焰，便于直接观察多势力和盟友情报。
- 关系验证拒绝缺失、重复、自相矛盾或未知势力对；关系进入 setup 克隆和哈希。
- AI 只把敌对关系作为合法目标；中立和同盟可被观察但不会被其非敌对方伤害，并参与实体碰撞、射线和动态阻挡。
- 同盟情报通过按接收势力独立节流的消息队列传播；消息保留观察 tick、送达 tick、来源和历史坐标快照，送达时不读取目标实时位置。
- 冲突终止按仍存续的敌对关系边计算；中立/同盟存续不会阻止稳定结束，结果可包含多个胜方。
- 模式有效战力把溃散/失效编组排除，保留失去机动但武器有效的固定火力，并排除武器失效的有人平台；该派生值通过本方 inspection 投影，不向敌方最后已知检查泄露实时状态。
- 编组级移动、成员级健康/最终位置和平台/部件结果。
- 健康状态与在场状态分轴记录。
- 本地目视发现、最后已知位置和同势力 15 tick 情报延迟。
- 弹匣、射击节奏、换弹和无限备用弹药。
- 同时伤害结算、成员受伤、失能和死亡。
- 压制、士气、溃散、撤离、重新集结入口。
- 冲突模式消灭/溃散、僵局和最大时长终止。
- 冲突/防守模式判别输入，冲突模式保持默认并向后兼容。
- 单个防守目标的占领、争夺、恢复、时限与胜负结算。
- 多目标防守目标数组、`all/count/sequence` 组合胜负、序列解锁与每目标状态投影。
- 防守编组按目标确定性分配前沿阵地和预备队阵位；预备队比例、分配目标与角色进入检查和状态哈希。
- 进攻编组按实际 A* 路径长度在已解锁目标间选择合法路线，目标 HUD、事件和结果覆盖全部目标。
- 防守方依据高程、移动成本、目标距离和分散度选择阵位。
- 进攻方在没有相关敌情时向目标推进，并以有效在场成员提供占领力。
- AI 决策刷新不会取消已经开始的单格移动；被静止友军持续挡路时会使用确定性的动态障碍 A* 绕行，友军遮挡射线时后排会寻找相邻射击位。
- 目标状态、占领进度、双方占领力、目标事件和检查接口。
- 增援入口与批次输入验证；入口只接受合法边缘格，批次按到达 tick 进入授权入口。
- 增援入口容量排队、入口敌控等待、替代入口和取消策略；增援进入使用新实体 ID，不复用死亡或失能实体。
- 增援触发、等待、进入和取消事件；未部署、已部署和撤离状态进入 BattleResult，未部署单位不参与感知、占领或伤亡统计。
- `getRenderFrame(observerFactionId)` 按全知或指定势力投影可见编组；未知敌军不出现在渲染帧，已知敌军只投影最后已知位置和接触时间。
- 乘员不重复输出为地面 `RenderMember`；平台通过独立 `RenderPlatform` 输出稳定 ID、视觉类型、位置、朝向和粗状态，本方平台可按 ID inspection，编组 inspection 提供平台摘要。
- 势力视角的编组/成员检查在模拟边界裁剪；本方保留完整检查，敌方已知接触不返回成员、健康、士气或路径真值。
- 模拟内部已按清晰所有权提取运行时初始化与 setup 深拷贝、稳定排序、无状态战斗/目标/车辆位置/运输评分，以及整数炮弹轨迹、supercover 碰撞和爆炸衰减；`simulation.ts` 继续独占权威状态和固定 tick 调度，炮兵展开在 AI 决策后、移动前推进，已有弹丸在移动后、射击收集前推进，并通过 `stage-3.7` 规则版本显式升级。

### 网页观察端

- React、TypeScript、Vite、Three.js 和 React Three Fiber。
- 模拟运行在 Web Worker，主线程只接收渲染帧和检查结果。
- 平滑高度地形，以及直接消费权威静态对象列表的实例化树木、岩石和墙体。
- 地表、水深和地面阻挡标志驱动的基础地形顶点色；深水、浅水和湿地水斑使用独立批量水面，静态对象不会生成在水体或保留路线中。
- 批量渲染的成员与势力编组标记。
- 基础轮式/履带平台模型、选择反馈、受损/摧毁色调，以及编组检查面板的平台机动、作战、乘员、乘客和受损摘要；有人操控的平台、乘客编组与编组标记共享格内连续位置并按帧时长统一插值，弃置或摧毁平台仍固定在独立权威格。

- 倾斜正交镜头、平移、旋转、缩放、复位和跟随模式；初始与复位缩放会按地图跨度和画布宽度自适应。
