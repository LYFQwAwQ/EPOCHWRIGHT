# 网页客户端与观察体验

> **文档角色**：网页、Three.js 和观察交互的目标设计
> **权威性**：体验与表现目标；当前 UI 事实以 `09` 和代码为准
> **何时阅读**：修改渲染、特效、镜头、观察模式、信息面板、控件、视角或前端性能时
> **可跳过**：无用户可见变化的模拟纯规则、数据迁移或 Git 操作
> **相关代码**：`src/App.tsx`、`src/render`、`src/ui`、`src/styles.css`

## 1. 技术方向

首版客户端采用：

- React：应用外壳、面板、工具栏和状态展示。
- TypeScript：客户端、模拟核心和地图生成共享类型。
- Vite：开发与构建工具。
- Three.js：3D 场景、地形、单位和特效。
- React Three Fiber：将 Three.js 场景接入 React 生命周期。
- Web Worker：运行战斗模拟，必要时另开地图生成 Worker。

React 不参与逐单位模拟，也不为每名士兵维护组件状态。战斗真相始终位于模拟 Worker。

## 2. 客户端分层

```text
React UI
  | pause / inspect / view selection
Client state and worker bridge
  | compact messages and render frames
Battle simulation worker
  | BattleSetup -> events / result
Pure TypeScript simulation core

Three.js renderer
  | consumes interpolated render frames
Terrain, instances, effects, overlays, camera
```

地图生成器可以在战斗初始化前运行于独立 Worker，输出标准 `BattleMap` 后即退出或复用。

地图层 TypedArray 需要同时服务地形渲染和战斗模拟。Worker bridge 在初始化时负责一次性克隆，或在转移所有权前生成独立的渲染副本；不能让主线程在转移后继续读取已经失效的缓冲区。动态单位状态仍只从模拟 Worker 单向输出。

## 3. 无美术资源的 3D 表现

基础几何体应形成一致的战术可视语言，而不是临时调试物体堆叠：

- 步兵使用胶囊体或简化人形轮廓，武器用短线或简单几何表示。
- 坦克使用车体盒、炮塔和炮管，炮塔方向独立于车体。
- 轮式、履带、火炮和运输平台通过轮廓与顶视标记区分。
- 直升机和无人机使用简单但可识别的俯视剪影。
- 英雄除势力颜色外具有独立形状标记，不只依赖发光效果。
- 地形颜色由地表、水深、高度和静态对象共同表达。

视觉定义通过 `visualTypeId` 与内容配置关联。以后替换为正式模型时，不改变模拟模板和实体标识。

## 4. 地形渲染

- 根据量化高度生成分块地形网格。
- 相邻格平滑连接，悬崖保持明确断面。
- 地表类型优先使用颜色、低成本纹理或顶点色表达。
- 水面与地表分层，不让深水仅靠颜色深浅区分。
- 网格线默认弱化，可在信息模式或调试模式增强。
- 大地图按区块构建、视锥裁剪和更新，不能每次状态变化重建整张地形。

静态树木、岩石和重复掩体使用实例化绘制，并直接消费标准地图中的稳定对象 ID、锚格与方向。建筑或大型目标可以使用独立网格；纯表现植被不得伪装成模拟中不存在的阻挡或掩体。

## 5. 单位实例化

### 5.1 原则

- 相同视觉类型和材质的成员批量使用 `InstancedMesh`。
- 车辆可按车体、炮塔等少量实例层分组。
- 不为每个成员创建 React 组件或独立材质。
- 实例索引由渲染适配层维护，不暴露为战斗实体 ID。
- 死亡、撤离或更换视觉类型时使用空闲表回收实例槽。

### 5.2 细节层级

- 近距离显示成员、武器方向和主要状态。
- 中距离简化阴影、动画和小型附件。
- 远距离按编组显示聚合标记或简化实例，但模拟继续完整运行。
- 镜头外只停止渲染，不停止战斗。

LOD 切换必须保持编组位置、势力颜色和伤亡规模可读，避免单位突然整体消失。

平台受损和摧毁通过保留原势力色相的分级压暗表达，不得因任一部件受损就把整个平台替换为统一灰色；状态详情仍以权威 inspection 和事件为准。

## 6. 表现事件

射击、命中、爆炸、发现和伤亡由 Worker 事件驱动。表现层可以：

- 抽样显示高速武器的曳光弹。
- 显示枪口火焰、随弹体移动且落地即消失的短曳光、弹着、爆炸和压制提示。
- 对慢速逻辑弹体插值显示真实轨迹。
- 播放简化的换弹、受伤、失能和死亡动画。

视觉效果不得回写伤害。效果丢帧或被质量设置关闭时，战斗结果必须完全不变。

逻辑弹体只消费 Worker 投影的当前三维位置，不在客户端重算轨迹、目标或预定弹着。敌方弹体和弹着事件遵守当前观察方裁剪；切换视角时不得保留上一视角的检查或事件。

## 7. 镜头

使用倾斜正交俯视镜头，默认朝北并保留足够倾角显示高度。支持平移、缩放、旋转和一键复位。

镜头模式与 UI 显示模式相互独立。

### 7.1 自由镜头

玩家控制平移、缩放和旋转。任何手动镜头操作都会退出自动导演，但不会改变 UI 显示模式。

### 7.2 跟随镜头

跟随选中的编组、平台或英雄，并保持用户当前缩放和方位。目标死亡、撤离或不可用时停止跟随并平滑停留在最后位置。

### 7.3 自动导演

导演按区域热点评分，候选因素包括：

- 交火人数和火力强度。
- 防守点争夺和占领变化。
- 突发高伤亡、平台摧毁或增援进入。
- 英雄能力或重要目标活动。
- 新接触和大规模机动交汇。

导演具有最短停留时间、切换冷却和位置差异阈值，使用平滑移动而不是频繁硬切。纯净 UI 与自动导演可以同时开启。

## 8. UI 显示模式

### 8.1 战术信息模式

提供：

- 顶部战斗状态与模式目标。
- 暂停/继续按钮。
- 势力视角和全知视角切换。
- 选中单位详情。
- 战斗事件摘要。
- 可选战术图层。

### 8.2 纯净观察模式

隐藏信息面板、选择轮廓、战术图层和大部分 HUD，只保留最低限度的暂停与退出控制。纯净模式不改变摄像机模式，也不取消当前选中对象。

### 8.3 开发调试模式

额外显示：

- 网格容量和拥堵。
- 路径、局部槽位和目标点。
- 视线、发现进度和接触可信度。
- 威胁图、影响图和防守位置评分。
- AI 当前状态、原因码及主要效用分数。
- 模拟 tick、Worker 延迟和各系统耗时。

调试模式可以单步和调整时间倍率，但这些功能不得出现在正式规则接口。

## 9. 单位信息

普通玩家可以点击查看详细信息。面板根据对象类型显示：

### 9.1 编组

- 势力、模板、当前任务和目标。
- 有效人数、伤亡和凝聚度。
- 士气、压制和简化体力。
- 当前接触信息及其可信度。
- 主要武器和换弹状态。
- 当前掩体覆盖人数，以及模拟提供的掩体选择原因、主要评分和已知威胁来源。

### 9.2 成员与英雄

- 伤亡状态、岗位和武器。
- 已生效状态与能力冷却。
- 英雄身份和外部传入的只读摘要。

### 9.3 平台

- 乘员岗位与乘客。
- 当前检查面板显示平台乘客组数，以及乘客编组的配对平台、搭载/下车/受困状态和动作剩余 tick；事件流显示动作开始、完成、取消与强制下车。
- 装甲方向、部件和结构状态。
- 机动、武器、观察设备及当前目标。
- 自行火炮平台显示展开状态、剩余动作 tick、任务来源、情报年龄/置信度、瞄准进度、误差和最近拒绝原因；这些字段由平台 inspection 提供，UI 不重新推导任务规则。

### 9.4 防守点

- 当前控制方。
- 占领进度、争夺状态和有效占领力量。
- 目标顺序、时限和模式权重。

## 10. 信息视角

- **全知视角**显示真实位置和完整状态，适合普通沙盘观察。
- **势力视角**只显示该势力已知地图、当前接触、最后已知位置和共享情报。
- 接触标记必须表达时间和不确定性，不能把过期位置绘制成真实单位模型。
- 切换视角只改变客户端过滤，不改变 Worker 中任何势力知识。

## 11. 交互与控件

- 熟悉的动作使用图标按钮，例如暂停、继续、镜头复位、跟随和显示/隐藏 UI。
- 不熟悉的图标提供简短 tooltip。
- 模式选择使用分段控件，二元图层使用开关或复选框。
- 工具栏尺寸固定，动态数字不能推动其他控件位移。
- 信息面板使用紧凑层级，不使用营销式大标题或装饰性卡片堆叠。
- UI 不显示大段操作说明；必要帮助放在 tooltip 或独立帮助入口。

## 12. 势力与地形可读性

- 势力不只依赖单一颜色，还使用轮廓标记、顶部图案或形状编码。
- 同盟、中立和敌对关系使用边框或标记表达，不能只靠红绿区分。
- 地表、水体、高度、选中态和威胁图层使用不同视觉通道，避免整个界面被单一色系覆盖。
- 文本、图标和状态条在常见桌面缩放下不能互相覆盖。

## 13. 性能预算

初始目标：

- 桌面浏览器常见分辨率下尽量保持 60 FPS 渲染。
- 模拟基础步长为每秒 20 tick，重大性能压力下优先错峰 AI，而不是改变时间流速。
- Worker 到主线程的常规状态传输不超过渲染所需字段。
- 地形最多按 `512 x 512` 网格设计，但必须分块。
- 大型预设目标为 200～500 编组、2000～5000 可视成员/平台。

性能优化优先顺序：

1. 消除全量两两查询。
2. 降低重复路径与视线计算。
3. 错峰非紧急 AI。
4. 减少 Worker 消息复制。
5. 实例化、裁剪和 LOD。
6. 降低非关键视觉效果。

不能通过停止离屏战斗或让镜头位置影响 AI 来达成性能目标。

## 14. 质量档位

提供低、中、高三个表现档位，可调整：

- 阴影和光照质量。
- 地形区块细节。
- 粒子、曳光和爆炸数量。
- 远距离成员聚合阈值。
- 静态装饰物密度。

质量档位不得改变命中、视线、单位数量或任何模拟规则。

## 15. 首版平台边界

- 优先支持桌面端现代浏览器。
- 使用广泛可用的网页 3D 基础能力，不把首版绑定到实验性渲染后端。
- 手机和平板只要求得到明确的不支持或降级提示，不承诺完整战斗体验。
- 页面失去焦点或浏览器限制后台执行时，客户端应自动暂停或明确显示状态，不能静默丢失模拟时间。

## 16. 首版不做的观察功能

- 战斗录像列表。
- 时间轴拖动和任意时刻跳转。
- 中途存档恢复。
- 在线分享与多人同步观看。

核心仍保留固定步长、事件日志和版本信息，为以后加入回放留下基础。
