## 1. 使用规则

- 本文只保存尚未完成的任务，不保存完成历史。完成后删除条目，并把实际能力更新到 `09-implementation-status.md`。
- `P0` 表示当前阶段闭环，`P1` 表示下一阶段准备或工程治理，`P2` 表示尚未拆解的长期能力。
- 状态使用 `ready`、`planned`、`needs-design`、`blocked`、`in-progress`。
- 开始开发前把任务改为 `in-progress`，并补充负责人或工作分支；同一负责人默认只保留一个主要进行中任务。
- 一个任务必须能够独立验收。超过一个垂直切片时，先按任务模板拆分，不直接开始编码。
- 新需求先与 `08-delivery-plan.md` 和相关领域设计核对；TODO 不用于静默改变产品规则。

### `VEHICLE-004` 乘员岗位与换岗

- 状态：`ready`
- 优先级：`P0`
- 目标：让驾驶、观察和平台武器能力真实依赖部件、岗位与成员状态。
- 范围：岗位资格、缺员降级、固定时间换岗、平台武器状态和能力派生；不含装甲穿透、弃车后重编或跨编组补员。
- 依赖：`VEHICLE-003`。
- 主要模块：内容验证、运行时状态、战斗纯规则、模拟调度、事件、inspection 和结果。
- 完成定义：关键岗位失能会停用对应能力，合格或允许替代的乘员经过确定 tick 恢复能力；换岗状态进入哈希且终止后冻结。
- 验证：岗位纯规则、同时伤情/换岗场景、固定 seed 复演、信息裁剪、`npm run check`。
- 文档：实现后更新 `09`、`11` 和实际事件/结果字段。

### `VEHICLE-005` 装甲、穿透与部件损伤

- 状态：`planned`
- 优先级：`P0`
- 目标：以方向装甲和独立部件/乘员伤害形成可解释的反载具交战闭环。
- 范围：正面/侧面/后方/顶部判定、穿透与外露部件效果、结构/机动/武器/传感部件、平台状态事件和弃车；不含复杂内部几何、维修、燃料或友军伤害。
- 依赖：`VEHICLE-004`。
- 主要模块：武器与平台内容、战斗规则、意图结算、AI 有效战力、事件、inspection、result、表现事件。
- 完成定义：失去机动的平台仍可射击，失去作战能力但可移动的平台会撤离；平台摧毁不会默认杀死全部乘员；方向和稳定随机键可逐 tick 复演。
- 验证：装甲面/穿透纯规则、同时伤害、部件与乘员场景、终止条件、固定 seed 哈希、`npm run verify`。
- 文档：实现后更新 `09`、`11`、`13` 的场景覆盖。

### `VEHICLE-006` 显式运输配对与自动上下车

- 状态：`planned`
- 优先级：`P0`
- 目标：让显式配对的步兵和运输平台在有限情报 AI 下完成可复演的搭载、机动、下车与乘客伤害。
- 范围：顶层运输关系、初始搭载、整组原子上下车、容量、取消/受困状态、重复上车和运输损毁结算；不含机会式搭载、部分小队拆分、射击孔或跨组调员。
- 依赖：`VEHICLE-003`、`VEHICLE-005`。
- 主要模块：setup/内容验证、成员位置轴、占用、AI、状态哈希、事件、平台检查/结果、UI。
- 完成定义：车内成员不占地面容量、不感知/射击/占领；只有配对编组可上下车；损毁后的幸存者和受困状态满足成员守恒且不重叠。
- 验证：容量/原子转换纯规则、运输长程确定性场景、目标占领负例、乘客伤害与结果守恒、Playwright 事件/检查、`npm run verify`。
- 文档：实现后更新 `09`、`11` 和观察端说明。

### `VEHICLE-007` 合成兵种 AI 与阶段验收

- 状态：`planned`
- 优先级：`P0`
- 目标：让步兵、战斗车辆和运输车辆在冲突/防守模式中按能力与有限情报协同完成任务。
- 范围：地面目标域/武器适配、装甲朝向与交战位置评分、运输下车时机、车辆有效战力、演示场景、观察可读性和规模回归；地图内炮兵另行设计，不混入本任务。
- 依赖：`VEHICLE-004`、`VEHICLE-005`、`VEHICLE-006`。

## 5. P2：后续里程碑候选

以下能力仍需在进入对应阶段前拆成可独立验收的任务，当前不要直接标记为 `in-progress`：

- `ARTILLERY`：地图内直接/间接火力、情报误差和炮组岗位。

- `META`：城市建造、角色养成、时代科技与战斗输入/结果的集成契约。

## 6. 新任务模板

```markdown
### `DOMAIN-NNN` 简短标题

- 状态：`ready`
- 优先级：`P0`
- 目标：一句话说明要形成的用户或系统闭环。
- 范围：列出包含内容和明确不包含内容。
- 依赖：任务 ID 或“无”。
- 主要模块：预计修改的所有权边界。
- 完成定义：可观察、可测试的事实。
- 验证：固定 seed、单元/场景/E2E/性能要求。
- 文档：需要同步的设计、状态和模块文档。
```
