## 1. 使用规则

- 本文只保存尚未完成的任务，不保存完成历史。完成后删除条目，并把实际能力更新到 `09-implementation-status.md`。
- `P0` 表示当前阶段闭环，`P1` 表示下一阶段准备或工程治理，`P2` 表示尚未拆解的长期能力。
- 状态使用 `ready`、`planned`、`needs-design`、`blocked`、`in-progress`。
- 开始开发前把任务改为 `in-progress`，并补充负责人或工作分支；同一负责人默认只保留一个主要进行中任务。
- 一个任务必须能够独立验收。超过一个垂直切片时，先按任务模板拆分，不直接开始编码。
- 新需求先与 `08-delivery-plan.md` 和相关领域设计核对；TODO 不用于静默改变产品规则。

## 3. P0：当前阶段闭环

### `ABILITY-002` 持续光环与来源生命周期

- 状态：`planned`
- 优先级：`P0`
- 目标：在被动能力基础上实现可追溯来源、范围、叠加和移除的持续光环。
- 范围：同编组或邻近格友军光环、稳定来源 ID、整数范围、明确叠加策略和离场/失能移除；不含事件触发与主动能力。
- 依赖：`ABILITY-001`。
- 主要模块：能力内容、空间查询、运行时状态、哈希、inspection/result、确定性场景。
- 完成定义：来源进入/离开范围、失能、撤离和死亡均在固定 tick 更新效果；同分与多来源按稳定 ID 处理，有限情报不泄露隐藏来源。
- 验证：范围边界、叠加/移除、来源生命周期、逐 tick 哈希、观察负例和 `npm run check`。
- 文档：实现前确定 `06 §9.3` 的叠加与来源契约。

### `ABILITY-003` 条件触发、主动能力与 AI 效用

- 状态：`planned`
- 优先级：`P0`
- 目标：完成条件触发与由 AI 自动使用的主动能力、冷却和次数闭环。
- 范围：注册式条件/效果/处理器、冷却、次数、合法目标与有限情报效用；玩家仍不能手动施放，不执行内容脚本。
- 依赖：`ABILITY-002`。
- 主要模块：能力运行时、AI 上下文、事件/inspection/result、Worker/UI 与场景测试。
- 完成定义：AI 只按可见上下文和通用评分使用能力，冷却/次数/稳定序号进入哈希，事件和检查可解释选择与拒绝原因。
- 验证：隐藏真值成对场景、冷却/次数边界、事件顺序、终止冻结、真实 Worker E2E 和 `npm run verify`。
- 文档：实现前确定主动目标、费用和事件契约。

### `HERO-001` 英雄编制、持久化身份与结果投影

- 状态：`needs-design`
- 优先级：`P0`
- 目标：让独立英雄和编入小队的英雄复用统一成员/能力规则，并完整返回外部持久化身份与最终状态。
- 范围：英雄成员槽位、稳定持久化 ID、重要度/能力引用、inspection 与 `BattleResult`；不实现升级、成长或战役存储。
- 依赖：`ABILITY-003`。
- 主要模块：内容与 setup 契约、运行时/结果、demo、观察 UI 和外部边界测试。
- 完成定义：两种编制形式都遵守成员健康/在场不变量，外部 ID 在迁移、克隆、哈希和结果中不丢失，不存在英雄专用生命体系。
- 验证：独立/编入场景、伤亡与撤离结果、ID 守恒、观察裁剪和 `npm run verify`。
- 文档：设计时明确 `03 §14` 与 `06` 的英雄输入/结果字段。
