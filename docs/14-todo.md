## 1. 使用规则

- 本文只保存尚未完成的任务，不保存完成历史。完成后删除条目，并把实际能力更新到 `09-implementation-status.md`。
- `P0` 表示当前阶段闭环，`P1` 表示下一阶段准备或工程治理，`P2` 表示尚未拆解的长期能力。
- 状态使用 `ready`、`planned`、`needs-design`、`blocked`、`in-progress`。
- 开始开发前把任务改为 `in-progress`，并补充负责人或工作分支；同一负责人默认只保留一个主要进行中任务。
- 一个任务必须能够独立验收。超过一个垂直切片时，先按任务模板拆分，不直接开始编码。
- 新需求先与 `08-delivery-plan.md` 和相关领域设计核对；TODO 不用于静默改变产品规则。

## 6. 新任务模板

```markdown
### `DOMAIN-NNN` 简短标题

- 状态：`ready`
- 优先级：`P0`
- 目标：一句话说明要形成的用户或系统闭环。
- 范围：列出包含内容和明确不包含内容。
- 依赖：任务 ID 或“无”。
- 主要模块：预计修改的所有权边界。
- 完成定义：可观察、可测试的事实。
- 验证：固定 seed、单元/场景/E2E/性能要求。
- 文档：需要同步的设计、状态和模块文档。
```
