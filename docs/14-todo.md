# 开发 TODO

> **文档角色**：近期可执行工作队列与优先级入口
> **权威性**：执行计划；产品语义以 `01-07` 为准，完成事实以 `09` 为准
> **何时阅读**：选择下一项工作、开始或完成任务、调整阶段优先级时
> **可跳过**：已经有明确任务 ID 的局部实现和与产品无关的紧急修复
> **相关代码**：全仓库；开始任务后依据任务路由确认具体模块
> **维护触发**：任务开始、完成、阻塞、拆分、取消或优先级变化

## 1. 使用规则

- 本文只保存尚未完成的任务，不保存完成历史。完成后删除条目，并把实际能力更新到 `09-implementation-status.md`。
- `P0` 表示当前阶段闭环，`P1` 表示下一阶段准备或工程治理，`P2` 表示尚未拆解的长期能力。
- 状态使用 `ready`、`planned`、`needs-design`、`blocked`、`in-progress`。
- 开始开发前把任务改为 `in-progress`，并补充负责人或工作分支；同一负责人默认只保留一个主要进行中任务。
- 一个任务必须能够独立验收。超过一个垂直切片时，先按任务模板拆分，不直接开始编码。
- 新需求先与 `08-delivery-plan.md` 和相关领域设计核对；TODO 不用于静默改变产品规则。

## 5. P2：后续里程碑候选

以下能力仍需在进入对应阶段前拆成可独立验收的任务，当前不要直接标记为 `in-progress`：

- `VEHICLE`：轮式/履带移动、装甲方向、部件、乘员岗位和运输。
- `ARTILLERY`：地图内直接/间接火力、情报误差和炮组岗位。
- `AIR`：旋翼/悬停空军、高度带、低空遮挡和空地目标域。
- `ABILITY`：通用被动、光环、触发、主动能力和英雄持久化 ID。
- `META`：城市建造、角色养成、时代科技与战斗输入/结果的集成契约。
- `LATER`：有限弹药补给、天气、地形损毁、回放和自动导演。

## 6. 新任务模板

```markdown
### `DOMAIN-NNN` 简短标题

- 状态：`ready`
- 优先级：`P0`
- 目标：一句话说明要形成的用户或系统闭环。
- 范围：列出包含内容和明确不包含内容。
- 依赖：任务 ID 或“无”。
- 主要模块：预计修改的所有权边界。
- 完成定义：可观察、可测试的事实。
- 验证：固定 seed、单元/场景/E2E/性能要求。
- 文档：需要同步的设计、状态和模块文档。
```

任务完成后不要保留勾选历史。更新 `09`、删除 TODO 条目，并让 Git 历史和提交说明保存过程记录。
