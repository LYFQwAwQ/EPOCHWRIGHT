# 文档上下文与阅读指南

> **文档角色**：文档系统导航与上下文加载策略
> **权威性**：流程规范；不定义具体战斗数值
> **何时阅读**：首次参与项目、任务范围不明确、跨模块设计或新增/拆分文档时
> **可跳过**：任务边界明确，且已能根据根目录 `AGENTS.md` 选定目标章节时
> **相关代码**：无；关联 `AGENTS.md`、`docs/README.md` 和全部编号文档
> **维护触发**：文档新增、删除、改名、职责变化或阅读路由变化

## 1. 目标

文档系统同时服务人类开发者和 AI。目标不是让每个参与者预先掌握全部设计，而是用最少的相关上下文做出可靠改动，并在风险提高时及时扩展阅读范围。

三个原则：

1. **渐进披露**：先读取不变量和任务直接相关章节，再按风险扩展。
2. **权威明确**：区分产品决策、目标设计、当前实现事实、工程规范和操作参考。
3. **质量优先**：减少无关阅读，不减少必要验证；不确定时增加上下文而不是猜测。

## 2. 四层上下文

| 层级 | 内容 | 默认行为 |
| --- | --- | --- |
| L0 | `AGENTS.md` 中的加载协议和仓库不变量 | AI 每个新任务读取 |
| L1 | `09` 当前实现状态、目标代码与相邻测试；选择工作时增加 `14` | 功能/规则/排期任务读取 |
| L2 | 一个领域设计文档 + 对应模块/扩展/测试章节 | 根据任务路由按章节读取 |
| L3 | 完整接口、工程约束、总体愿景或多个领域文档 | 仅在跨模块、冲突或新系统时读取 |

L0 不是全部架构知识，而是能够避免严重错误的最小集合。L2 通常已经足够完成一个边界清楚的任务。

## 3. 权威层级

发生冲突时按以下方式处理，而不是机械选择优先级：

| 文档/来源 | 表达内容 | 处理方式 |
| --- | --- | --- |
| 用户最新明确决定 | 产品意图 | 最高优先，必要时同步设计文档 |
| `01` 与对应领域 `02-07` | 已确认产品规则和目标设计 | 规则实现应遵循；未实现不等于缺陷 |
| `09` + 当前代码/测试 | 当前已实现事实 | 用于判断现状；与目标设计不同要标为缺口 |
| `10` | 工程与架构不变量 | 所有实现必须遵守，偏离需明确架构决策 |
| `06` | 目标边界契约 | 当前 TS 类型是运行事实，扩展时两者必须对齐 |
| `08` | 路线和风险 | 规划参考，不代表功能已经实现 |
| `11-13` | 模块、扩展和操作参考 | 与代码漂移时应修正文档，但先核实行为 |
| `14` | 尚未完成的执行队列 | 用于排序和领取工作，不能覆盖产品规则或完成事实 |

如果代码与产品规则冲突，不能静默把代码当成新设计；先判断是 bug、阶段性限制还是文档过期。

## 5. 高效阅读方法

### 5.1 先搜索，再打开

```powershell
rg -n "关键词" src docs
rg -n "^#{1,3} " docs\06-data-and-interfaces.md
```

先确认目标符号、调用方、测试和文档标题，再读取匹配章节。不要因为文件名相关就直接加载整个长文档。

### 5.2 优先读文档头

每份文档开头说明：

- 文档角色；
- 权威性；
- 何时阅读；
- 可跳过条件；
- 相关代码。

读取文档头后发现任务不匹配，应停止加载该文档。

### 5.3 章节级读取

长文档 `02-08`、`10-13` 默认按章节读取。例如修改目标占领规则，只需要先读：

- `05 §4 防守模式`；
- `10 §2/3/4`；
- `11 §3` 中 `objective.ts` 和 `simulation.ts`；
- `12 §7`；
- `13 §1.2/5`。

不需要同时读取空军、载具、完整 UI 或所有发布流程。

## 6. 典型任务路由

### 修复曳光不可见

最小阅读：`07 §6`、`11 §6`、`13 §1.3/7`，然后直接检查 `ShotEffects.tsx` 和 E2E。无需读取地图 schema、外交或完整战斗结算。

### 新增沼泽地形

读取：`09`、`02 §3-4/7`、`06 §5-6`、`10 §2/4/6`、`11` 的 map/path/render 小节、`12 §3`、`13` 测试矩阵。因为涉及 schema、规则和渲染，应升级到 L3 的接口上下文。

### 新增同盟情报

读取：`09`、`04 §4-5`、`06 §7/13/16`、`10 §2/5/6`、`11` 的 sim/worker 小节、`12 §8`、`13 §1.2/4-6`。无需读取载具和空军章节。

### 只改 README 或命令说明

读取目标文档头、`docs/README.md` 和实际 `package.json`。除非描述战斗能力，否则不需要读取全部设计文档或模拟实现。

## 7. 质量升级条件

最小上下文不足的信号：

- 无法确定状态属于模拟、客户端还是渲染；
- 同一字段出现在输入、运行时、帧和结果多个边界；
- 需要修改版本号或兼容旧数据；
- AI 需要新的信息来源；
- 改动会改变同 seed 的结果；
- 一个修复需要在三个以上目录中复制逻辑；
- 测试无法用现有公开接口表达。

出现这些信号时，扩大到相关完整章节，必要时做架构评审。减少 token 的正确方式是排除无关领域，不是跳过直接相关的复杂性。

## 8. 防止文档膨胀

- 新内容先判断能否加入现有文档的明确章节。
- 只有出现新的读者、权威类型或独立维护周期时才新建文档。
- 同一规则只在一个权威位置完整定义；其他位置写一句摘要并链接。
- 当前数字、测试数量和限制集中在 `09`，避免散落后过期。
- 模块文件变动时更新 `11`，扩展步骤变化时更新 `12`，命令/CI 变化时更新 `13`，开放任务变化时更新 `14`。
- 每次新增文档都要更新本文件和 `docs/README.md`，并说明它替代或补充什么。
