# 世界、网格与随机地图

> **文档角色**：地图、空间和环境的目标领域设计
> **权威性**：目标设计；当前完成范围以 `09` 和代码为准
> **何时阅读**：修改网格、高度、通行、地形、水体、区域、地图生成或环境接口时
> **可跳过**：不改变空间规则的战斗数值、UI 文案和仓库维护
> **相关代码**：`src/sim/map.ts`、`pathfinder.ts`、`setup.ts`、`src/render/Terrain.tsx`

## 1. 坐标与网格

### 1.1 基础尺度

- 地图使用正方形网格。
- 默认网格边长为 `4 米`，该值保存在地图元数据中，不写死在算法里。
- 逻辑坐标使用整数格坐标 `(x, z)`；高度单独保存。
- 移动允许上下左右及四个对角方向。
- 对角移动成本按距离增加，并禁止从两个不可通行格形成的夹角中斜穿。

`4m` 网格在人员密度、掩体粒度和大地图成本之间取得平衡。典型 8 人小队会分布在 2～4 个相邻网格，而不是把所有成员压缩到一个点。

### 1.2 容量与拥挤

网格同时具有舒适容量和硬容量：

- 开阔地默认舒适容量为 4 名步兵。
- 开阔地默认硬容量为 8 名步兵。
- 平台按照自身尺寸换算为占用值，不直接等同于人数。
- 地形、姿态表现和掩体槽位可以修改容量。
- 超过舒适容量后产生移动、展开和爆炸易损惩罚。
- 正常移动不得超过硬容量；近战争夺允许短时超限。

容量是通行与局部阵型约束，不代表每名成员都在网格中心。表现层使用网格内部的阵型槽位绘制具体位置。

## 2. 混合高度系统

高度采用“量化存储、连续使用、平滑表现”的折中方案。

### 2.1 存储

- 每格保存固定精度高度值，默认每个高度单位为 `0.5 米`。
- 逻辑层使用整数高度单位，避免任意浮点误差。
- 相邻格之间根据高度插值得到地表采样值。
- 地图元数据保存高度单位，允许特殊地图调整精度。

### 2.2 移动

- 根据相邻格中心和共享边的高度差计算坡度。
- 每种移动类型配置舒适坡度、减速坡度和不可通行坡度。
- 高度骤变可以显式标记为悬崖边，不允许普通陆军通过。
- 轮式、履带式和步行单位使用不同坡度阈值。
- 空军不受地表通行限制，但低空飞行必须满足安全离地高度。

### 2.3 视线与弹道

- 观察点使用单位眼高或传感器高度。
- 目标点使用可见轮廓高度，而不是地面中心。
- 视线沿两点间射线采样插值地表和障碍高度。
- 山体、高地、建筑和树林可产生完全遮挡或部分遮挡。
- 高地优势来自更好的视线、射界与目标暴露，不使用过强的固定伤害加成。

### 2.4 3D 表现

地形网格根据量化高度生成平滑坡面。悬崖位置使用断面或陡峭连接，不把整个地图显示为阶梯。渲染插值不能反向修改逻辑高度。

## 3. 网格数据分层

每格不是单一地形枚举，而由多个正交层组成。

### 3.1 地表层

描述主要材质与承载特性，例如：

- 草地
- 沙地
- 泥地
- 岩石
- 铺装道路

地表影响移动成本、轮式/履带适应性、隐蔽性和视觉材质。

### 3.2 水体层

保存是否有水及量化水深：

- 无水
- 浅水
- 深水

通行性由水深与单位涉水能力共同决定。深水不会被写死为所有单位不可通行，以便未来支持两栖或水上平台。

### 3.3 高度层

保存地表基准高度、悬崖边及必要的坡面元数据。

### 3.4 静态障碍与掩体层

保存树木、岩石、墙体、建筑、战壕等对象。首版对象不可摧毁，但具有：

- 移动阻挡与占用值。
- 高度、轮廓和视线遮挡率。
- 弹道遮挡与防护类型。
- 可用方向和掩体槽位数量。
- 隐蔽加成。
- 防守位置评分修正。
- 预留的耐久、破坏状态和替换对象字段。

静态对象自身的阻挡格与相邻可站立掩体槽位必须分离。方向统一量化为 8 向整数，当前约定 `0=+z`、`2=+x`、`4=-z`、`6=-x`；方向性防护和渲染朝向使用同一约定。

阶段 2 的槽位由静态对象稳定 ID、类型、锚格和朝向确定性派生，不复制进地图图层：朝向法线背后的相邻可通行格形成一个候选槽位，越界、不可通行或已被更小稳定 ID 槽位占用时不生成。树木、岩石和墙体分别覆盖最多 2、4、6 名有效成员。来自正面 45 度内的威胁获得完整效果，正侧面获得一半，侧后方和后方不生效；未覆盖成员按容量比例稀释整个编组的命中与发现修正。

槽位定义从只读地图派生，当前占用属于动态模拟状态。编组到达槽位后占用，完成离开、撤离或失去全部有效成员时释放；AI 是否主动选择槽位属于独立规则。

### 3.5 临时效果层

预留烟雾、火焰、积水、污染等区域效果。首版不启用动态天气，也不要求实现全部临时地形效果。

## 4. 组合地形

山脉、沼泽等概念由多层组合产生，不作为包含全部规则的特殊枚举。

| 地形概念 | 典型组合 | 主要作用 |
| --- | --- | --- |
| 山脉 | 高海拔、岩石地表、陡坡、悬崖 | 阻挡移动与视线，形成高地和通道 |
| 浅水 | 任意地表、较低水深 | 步兵和部分载具减速，降低容量 |
| 深水 | 较高水深 | 普通陆军不可通行，两栖单位按能力处理 |
| 沙地 | 沙质地表 | 轮式或步行成本提高，掩体通常较少 |
| 沼泽 | 泥地、浅水、低承载 | 大幅降低部分陆军速度，形成自然阻滞区 |
| 道路 | 铺装地表、低阻力 | 提高轮式与履带行军效率，容易形成可预测路线 |

具体修正放在移动类型与地形属性的匹配表中，不能散落在寻路代码里。

## 5. 空中空间

空军不占用地面容量。空中空间使用低空、中空、高空三个战术高度带，并在高度带内保存相对当前地表的精确量化离地高度。高度带用于安全容量、AI 和武器目标域等离散规则；离地高度使用整数毫米并按地图 `heightUnitMm` 对齐，用于视线、避障和渲染投影。二者不能互相替代。

- **低空**：可利用山体遮挡，但需要避障且容易遭到近程地面火力攻击。
- **中空**：视野和机动较好，地形遮挡减少，暴露程度提高。
- **高空**：主要服务于侦察或特殊任务，首版内容有限。

同一空中格和高度带仍有安全容量，避免多个平台完全重叠。该容量不复用地面 `occupancyUnits`：每个平台模板声明水平安全半径，同一高度带内任意两平台的格心距离必须不小于双方安全半径之和；不同高度带与地面实体互不占用容量。移动预约和出生验证使用同一距离规则，并按稳定平台 ID 解决同时移动冲突。

悬停平台模板为每个支持的高度带给出默认离地高度，spawn 显式选择初始高度带。运行时以每跨一带 `20 tick` 推进爬升/下降，离地高度按地图 `heightUnitMm` 量化插值；动作期间源带、目标带及中间带都声明安全容量，水平移动暂停。低空水平步骤必须以当前绝对高度越过目标格地形/静态对象并保留 `2m` 安全余量，否则 AI 先选择更高的合法高度。高度只由模拟推进，渲染端仍只做帧间插值。

## 6. 地图功能区域

### 6.1 出生区域

出生点实际是包含多个合法网格的区域。部署器根据编组尺寸、移动类型和容量选择具体位置。出生区域不能与目标区、悬崖或不可通行区域非法重叠。

### 6.2 增援入口

- 位于地图边缘的区域。
- 配置允许使用的势力或关系组。
- 增援由时间、模式事件或外部场景条件触发。
- 入口被敌军控制或容量不足时，增援进入延迟。
- 增援是预先配置的新部队，不是阵亡单位复活。

### 6.3 撤离出口

入口默认可以兼作本方出口，场景也可配置独立出口。成功离开出口的单位记为撤离。不存在安全路径时，溃散单位寻找隐蔽区并尝试重新集结。

### 6.4 防守目标区

防守点是一个网格集合或由几何区域栅格化得到的区域。目标区应提供：

- 明确边界。
- 占领容量与占领权重规则。
- 可选的占领顺序和前置目标。
- 防守方控制状态和进攻方进度。

## 7. 随机地图生成模块

### 7.1 模块边界

地图生成器接收 `MapGenerationRequest`，输出经过验证的标准 `BattleMap`。战斗核心不调用噪声、侵蚀或地貌生成算法。

同一个生成器版本、种子和参数必须生成相同地图。地图数据保存生成器版本，防止算法升级后无法复现旧地图。

### 7.2 可配置参数

- 地图宽高和网格尺寸。
- 随机种子。
- 平均海拔、整体起伏和局部粗糙度。
- 山脉密度、宽度、连续性和方向偏好。
- 水体比例、河流数量、湖泊规模及水深分布。
- 沙地、泥地、岩石、草地和沼泽占比。
- 树木、岩石、墙体等静态掩体密度。
- 开阔地比例、道路密度和狭窄通道倾向。
- 势力、出生区域、增援入口和防守点数量。
- 自然度与公平性权重。

参数应提供小型、中型、大型及“山脉密集”等预设，同时允许高级配置覆盖单项值。

### 7.3 建议生成流程

1. 根据种子生成基础高度场。
2. 叠加山脉走向、局部高地和低洼区。
3. 平滑、量化并识别悬崖与坡度。
4. 生成水系和水深。
5. 根据高度、湿度、坡度和参数分配地表。
6. 生成道路、通道和静态掩体。
7. 生成候选出生区、入口、出口和目标区。
8. 构建各移动类型通行图。
9. 执行连通性、容量、路线和目标可攻防性验证。
10. 自动修正局部问题；无法修正时使用派生种子重试。
11. 输出地图、生成报告和平衡评分。

### 7.4 自然不对称与平衡评分

地图不要求镜像或完全对称。生成器只保证每方具有基本作战空间和至少一条可行路线，再计算而不强行消除以下差异：

- 出生区到目标的路径距离。
- 可利用高地和掩体数量。
- 主要通道宽度和替代路线数量。
- 炮兵阵地、观察位置和空中遮挡条件。
- 各移动类型的可达面积。

严重失衡的地图自动重试；中等差异作为地图特点保留。平衡评分随地图一起输出，场景可以据此筛选。

### 7.5 验证条件

生成地图至少满足：

- 所有出生区域可容纳初始编组。
- 每个地面势力至少能到达其必须完成的目标。
- 防守点不能完全被不可通行地形封死。
- 防守点至少存在一条主进攻路线，默认应尽量存在第二条可选路线。
- 增援入口与出口具有合法落位空间。
- 深水、悬崖和掩体对象不存在非法重叠。
- 地图边界和空中安全高度有效。

## 8. 环境接口

地图和战斗输入预留静态环境参数：

- 环境亮度和昼夜阶段。
- 雨、雾、风及温度标签。
- 视距、发现、弹道、烟雾和地表状态修正入口。

首版所有修正均为中性值，不实际模拟天气。环境系统以后启用时，必须通过标准修正接口影响传感器、移动和武器，不能直接修改表现层来伪造规则。
